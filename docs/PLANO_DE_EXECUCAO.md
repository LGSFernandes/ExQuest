## Notas técnicas descobertas

- A skill `design-taste-frontend` só trouxe o `SKILL.md` (sem scripts/references/assets): apliquei as regras manualmente e verifiquei com Playwright próprio. Skill `frontend-design` usada para a direção (papel/tinta/marca-texto; folha de respostas como elemento marcante).
- Páginas `termos` e `privacidade` têm texto provisório: precisam de texto jurídico do responsável.

- Teste de `url_interna_segura` encontrou open redirect real: `/\evil.com` (navegador trata `\` como `/`). Corrigido.
- Regra de XP decidida: recompensa só na 1ª resposta correta de cada questão por usuário (chave `resposta:{uid}:{qid}`); repetições contam para estatística/revisão, sem XP/moedas.
- `slug` do catálogo: a migration gerou slugs a partir de `css_class` (ex.: `border-galaxia`); decisão: o slug dos itens existentes é mantido (= `css_class`, ex.: `border-galaxia`, `badge-veterano`) e `niveis.recompensa_nivel_catalogo()` usa esses mesmos slugs; o seed casa por `css_class` (ou nome, p/ boosts) e nunca altera preço de item existente.

- Alembic + SQLite: `PRAGMA foreign_keys=OFF` abre transação implícita; sem `connection.commit()` logo depois, o carimbo de versão é descartado (DDL aplicado, versão não). Corrigido em `migrations/env.py` e coberto pelos testes.
- `instance/database.db` do projeto é byte a byte o original (sha256 em `ExQuest_backups/SHA256SUMS_original`); todos os testes de migration usam cópias.
- O banco real tem 3 usuários, 1 compra de moedas `pendente` (nunca creditada; permanece como histórico legado), 0 pagamentos de assinatura, 0 `pagamento_historico` (sem dados de cartão para sanitizar).
